# The public API, reshaped once for 1.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every breaking API change of the spec in one release (0.3.0): static entry points, one problem shape, unique names, explicit one-shot reads, results that hold still, and a cancellable `MoveToSheet`.

**Architecture:** Mostly renames and reshaping of public types, with behaviour unchanged. Each task keeps the whole solution building and the whole suite green, and is its own Conventional commit (`feat!:`/`refactor!:` with a `BREAKING CHANGE:` footer) on one branch, `api/1.0`. One PR at the end is merged by rebase, so each commit reaches the changelog.

**Tech Stack:** .NET 8 + 10; xunit v4 on Microsoft.Testing.Platform; PublicApiAnalyzers; package validation against 0.2.0.

**Spec:** `docs/superpowers/specs/2026-09-27-api-for-1.0-design.md`

## Global Constraints

- No package references in the library; only the base class library.
- Error codes, never messages — the precheck's `Detail` prose goes; data becomes fields.
- Rows are views; no per-row allocation added on the read path (the renames must not touch it).
- Every reading operation takes a `CancellationToken` as its last parameter.
- A stream handed over is closed on every path unless `LeaveOpen`.
- Tests use only the public API.
- No `[Obsolete]` bridges: old names are removed.
- `main` is protected: the work lands through one PR with a green `CI Success`.
- Nothing from the local fixture folder appears in code, docs or commits.

## Rulings made while planning

- **`ImportField` stays constructible, not abstract.** A schema whose field types come from configuration builds `new ImportField { Name, Type }`; an abstract base would make that impossible. Typed subclasses (`TextImportField`, …) keep the fluent rules. Cost if wrong: none; a caller who wants only typed fields uses the factory.
- **`ImportSchema` compares by reference too**, with the fields it holds. Its list of reference-equal fields makes value equality meaningless. Cost if wrong: two schemas built alike are not `Equals`, which nothing relies on.
- **Renames are applied by a script over `*.cs`, `*.md` and `mkdocs.yml`**, with whole-word matches. `docs/superpowers/` (history) and `CHANGELOG.md` are excluded. Public API files are regenerated from the analyzers' RS0016/RS0017 output.

## Review Focus

1. A plan persisted with the old property names (`SourceColumnIndex`, `TargetFieldName`, `SourceHeader`) no longer deserialises. The changelog says so, and the table names each rename.
2. Equality of a `MappingPlan` must include `Bindings` order and each binding's `TreatAsEmpty` list, with hash codes consistent with `Equals`.
3. `ReadRows` is lazy: the "reads once" guard must trigger on enumeration, not on the call. A second `ReadRows()` call without enumerating the first is legal only if the first never started.
4. A `Summary` read after a run was disposed mid-way still returns the counts so far.
5. `MoveToSheet(i, cancelled)` must leave the cursor usable after the `OperationCanceledException`, or fault it clearly. It must not leave it half-moved and silently misread.

Each has a test in its task.
